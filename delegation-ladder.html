A new session is the last resort, not the default.

Creating a task session for every piece of work is the heaviest way to delegate: a runner, maybe a sandbox, a new harness. The main session can pick the lightest option that fits. Six rungs, one report format, one task list.

Session: an Omnigent session. Main session talks to you; task session does work.Prompt: your prompt is what you type; the assembled prompt is what the main session gets each time it wakes up.Helper: an agent loop that runs inside the main session, with its own clean prompt, and no session of its own.

What happens where

3exists in rakazo

Helper inside the wake-up

The main harness calls a tool that starts a nested agent with an empty history and a brief. Its final text comes back as the tool result. rakazo: pi-runtime.ts:1072–1268, max 4 in parallel, no nesting, results ≤ 12,000 characters.

ProsNo session, no runner start, parallel, context isolated
ConsDies with the wake-up; the main session waits; same engine
4new in Omnigent

Background helper

Like 3, but asynchronous. run_task returns a handle at once, the runner keeps the helper loop running (an OpenAI Agents Runner.run or a pi-agent-core Agent), and its steps are saved as collapsed items in the main session's history.

ProsOutlives the wake-up, parallel, still no new session
ConsNew runner feature; in-process SDK engines only; shares the runner's sandbox
5mostly exists

Worker from a pool

A few long-lived task sessions per user, reused. sys_session_send with a session_id already continues an existing session. Between tasks the worker gets a fresh harness and a clean prompt, so tasks don't leak into each other.

ProsNative engines, sandbox, no create cost
ConsOne task per worker at a time; needs a reset between tasks
·considered, not chosen

Lanes in one session

The main session's harness is fresh every wake-up anyway, so the session is only a container: the assembler could build a task lane's prompt instead of the main one. Rejected because lanes take turns (no parallel work) and the timeline becomes hard to read.

ProsOne session, full assembler control
ConsSerial; mixed history
