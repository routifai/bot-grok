# The artifact studio

> **Status:** Accepted 2026-10-17, refined the same day against the engine after review. Slice 1 built 2026-10-17 (`536c83872`..`0d33d58be`: group id, `editor` type, find-or-create, isolation, base-checked saves, studio notices, the studio surface); slice 2: its engine half built (`artifact_patch`, the stale notice and the "being edited" hint mark, live updates waiting on a studio turn, studio turns as activities, the warm runner with its open signal and the three-turn cap, the slide outline); its web half built (activity grouping, `artifact_patch` steps, stale and queued notes, phone layout, Escape and focus). Amends [ADR 0021](0021-one-conversation-messages-link-to-artifacts.md): edits made while a file is open go to that file's own chat, not to the Conversation. Mock-up: https://claude.ai/artifact/PrNmCjw77Yq3odNyyYgHZJ

ADR 0021 put every message in the one Conversation and linked messages to artifacts with a chip. For editing a file, that is the wrong shape. A run of changes to one deck ("bar chart", "biggest first", "shares on the bars") fills Super Chat with talk nobody needs there, and the assistant's context with it. When the person comes back to the deck a day later, those changes are scattered between other topics, and the history of the file is not where the file is. People edit a file in one place, by talking and by hand, and expect that place to remember.

The file remembers; Super Chat forgets.

## Decision

- **Opening is not editing.** The file card opens the file beside Super Chat, as today: read, present, export.
- **Editing opens the studio.** *Edit*, or starting to type in the panel's "Ask superchat to change this file…", opens the file in a full-window studio over the app: the slide navigator, the canvas editor that exists today (`features/artifacts/editor`, unchanged), its inspector, and the file's own chat beside them. Text typed in the panel's box travels into the studio composer with the caret where it was. "‹ Super Chat" closes it and returns to where the person was, with the panel still open on the file at its newest version.
- **Edit exists for what the editor can show.** Decks and HTML pages, Markdown and text, CSV and XLSX sheets. A PDF, DOCX, PPTX or image has no canvas: its panel keeps Open, export and the Library, and no studio; a request to change one is made in Super Chat and produces a new version there, as today.
- **One chat per file, for its whole life.** Each file has one studio chat, kept across every version and every visit. It holds the person's requests and the assistant's replies, the person's hand edits ("You made the title larger"), and a marker for every version saved, whoever saved it. Selecting an element on the canvas scopes the next request with the existing element chip (`Slide 3 · region-chart`).
- **Isolated from Super Chat.** The studio chat never appears in the Conversation's transcript and never enters its context. The Conversation learns that the file has a newer version through the artifact hint it already gets at the start of each turn (ADR 0021), and that a hand edit landed through the write-back note it already gets ([artifacts.md](../artifacts.md#write-back)). A message sent in Super Chat about a file still links with the chip and still edits the file; the studio shows that version with a "From Super Chat" marker.
- **Versions point at what made them.** The version menu reads one of five origins: from this chat, from Super Chat, by you, restored, updated from source. Choosing a studio version shows it and highlights its message in the studio chat; choosing a Super Chat version offers "Show in Super Chat", which closes the studio and scrolls to the message. Restore saves a new version, as today.
- **While the assistant works, the canvas is read-only.** A studio turn lights the canvas (ADR 0023's working state over the slide it is changing) and takes no hand edits until it saves or ends; selecting elements and typing the next request stay open. The canvas follows each save as it lands, unless the person is looking at an older version, which is never taken away from them.

## Engine shape

- **The studio session.** A child of the Conversation, kind `sub_agent`, created the way the daily-note passes are (`start_adhoc_helper`: `wake_parent=False`, no undelivered-dispatch label), so its turns never post a wake notice and never steer the Conversation. Its helper type is `editor`. It carries the label `superchat.artifact_chat` whose value is the file's **group id**: a new stable id on the artifact group (`owner`, Conversation, name), kept across versions and a future rename, which every version row and the artifact response carry. Labels are one value per key with no uniqueness across sessions, so find-or-create is made safe the way `muse.py` makes the Conversation unique: the session id is derived from (owner, Conversation, group id), a duplicate create is caught and re-read, and the label table gains an index on (key, value).
- **Find-or-create.** `POST /v1/artifacts/{id}/chat` takes any version id, resolves the group, and answers `{session_id, created}`. It needs owner access to the Conversation, never wakes the host, and is the only way a studio session is made. A deleted file archives its session; the route answers 404 for it.
- **The `editor` type.** Its own `config.yaml` under the bundle, runs on the person's Default model, with: `artifact_save`, `artifact_list`, a new `artifact_patch` (the same deterministic operations the inspector uses, `patches.py`, addressed by `data-superchat-id`), `deck_check`, `deck_export`, the `files_*` tools, `sys_os_*`, `session_history`, `memory_search`, `memory_get`, `memory_remember`; no `start_helper`, no `report_progress`, no `raise_flag`. It is outside the step limit, outside the helper concurrency count and every type's `max_sessions`, and has its own cap of three running studio turns per host (a fourth queues with "Finishing another file first"). It is excluded from session listings.
- **The editor prompt.** Not the Conversation's bundle text. Its rules: edit this file in place at its workspace path; prefer one `artifact_patch` to a rewrite; one `artifact_save` per request, carrying `base_version`; reply in one line that says what changed, no plan card, no delegation, no narration of mechanics; a standing preference the person states for their files ("never red in my decks") goes to memory with `memory_remember`, a one-off request never does.
- **What a turn sees.** The per-turn prefix for an editor session is: the file line (name, kind, group id, newest version, who saved it and when, workspace path), the write-back notes for this file, the memory profile, and for a deck the slide outline (slide number, element ids and their text, derived by code), so most requests are answered without reading the whole file. No Projects list, no recall hint. Write-back and the hint both resolve the Conversation through the same rule saves use (`chat_id`: the parent for a helper), scoped to the group; today both look up the calling session's own id and would find nothing for a child.
- **Saves.** The studio saves through `artifact_save` into the same group, so versions, the card and the Library update as they do now. An editor save carries `base_version`; a save whose base is not the group's newest version is refused with `artifact_stale`, and the editor re-reads before saving again. `all_versions[].item_id` for a studio save is the studio turn's own message. Link-on-save in `message_artifacts` is skipped for editor sessions. A `deck_export` from the studio lands in the group's Conversation like any helper's file, is listed in the studio chat and the Library, and makes no card in Super Chat.
- **Hand edits.** Each `manual` version (one per editor patch today) is recorded in the studio session as a stored runtime item, `[you] <edit_summary> · v<version>`, written to the session store without a runner dispatch, so it never starts a turn; during a running studio turn the same line is steered in, as hand edits steer the Conversation today. Versions from any other origin (Super Chat, a helper, a live update, a restore) are recorded the same way with their origin, so the editor knows what changed under it. The studio thread renders consecutive hand edits to one element as one row ("You changed the title · 12 edits · v3 → v14"); storage is one item per version.
- **Context over time.** Rollover applies to the studio session as to any superside-chat session; the rollover's working list keeps the standing instructions for this file, and the version list is the durable record of the file. Memory upkeep does not read editor sessions (they are helpers to it); what the person wants remembered from the studio goes through the editor's `memory_remember`. The studio's turns are not indexed for recall; recall finds the file.
- **Runner.** One runner per session: the studio's runner stays warm while the studio is open and for ten minutes after, then is released; the next request cold-starts it. First-token time for studio turns is logged under its own name, beside the Conversation's.
- **Host.** Opening the studio, reading versions and hand edits are engine-only and never wake a sleeping host. The first request wakes it, with the same "starting your machine" state the Conversation shows. A file whose `source_path` is empty or missing in the host is materialised from its newest bytes into `your_files/artifacts/<name>` by the editor turn before it edits.

## Concurrency

Two sessions can write the same file: the studio, and the Conversation or one of its helpers (drafts are versions, ADR 0022; live updates; restores). The rules:

- **Versions are never lost.** Every save is a version. The rules below decide only which bytes are the newest.
- **The studio is the base-checked writer.** Its saves carry `base_version` and are refused when stale. The Conversation's saves do not carry one (today's helpers), and are accepted.
- **A write from elsewhere during a studio turn** posts a notice into the studio ("Super Chat saved v9 while you were editing; v10 is based on v8") and the editor's next save is stale, so it re-reads. The Conversation's hint marks a file whose studio turn is running: "being edited in its studio", and the assistant's rule is to tell the person rather than edit it then.
- **Live updates wait** while the file's studio has a running turn, as they already wait ten minutes after a hand edit.
- **Hand edits during a studio turn** cannot happen: the canvas is read-only for the turn (Decision). The server rule above is the guard, not the UI.
- **Write-back writes only the studio's own file** at the start of a studio turn, and only versions not yet delivered, so a helper holding another file open is not touched.
- **Two tabs on one file** share one session: both see the same thread over the family stream, a second send while a turn runs is steered into it, and both canvases follow saves for the group.

## Web

- A studio surface (`features/artifacts/studio`) hosting the existing editor and a chat column, opened from the panel's Edit and composer. The chat column sends to the studio session, not the Conversation (`useArtifactAsk` today sends with `botId` to the Conversation; it gains a session target). The thread is the session's transcript merged with the group's version list by time; no new item kind.
- The main composer keeps `context.openArtifact` (ADR 0021 soft scope, case 1) when the panel is open. Only the panel's own Ask box moves to the studio.
- The studio subscribes to the family stream for its session and for `artifacts.changed` on its group, reloads the canvas on a save unless an older version is shown, and shows a "since you were here" divider above versions saved since the last visit.
- Leaving the studio mid-turn does not stop the turn; the card in Super Chat shows "updating" as it does for a helper's draft.
- The activity panel shows one activity per studio turn, titled from the request, grouped under the file's name; the editor session itself is never one row. The Conversation's work strip and Helpers list never show it.
- Mobile: the studio is the first layout that fits a phone; the canvas on top, the chat as a sheet below, the navigator as a strip.
- Keys: Escape closes the studio when nothing is selected and no menu is open; focus returns to the file card. The back control is named "Back to Super Chat".

## Consequences

- Engine: the `editor` type and prompt, `artifact_patch`, the group id, `base_version` on `artifact_save`, the find-or-create route, the label and its index, stored notices without dispatch, scoped write-back and hint for a child, the studio cap, the warm-runner rule, the file-materialise rule. No new table: the session store and the artifact store hold everything.
- Web: the studio surface, the session-targeted send, the merged thread, the five version origins, the activity grouping. The editor itself does not change.
- ADR 0021's "soft scope" from the panel's own box is replaced by the studio. The relink route, the chip on Super Chat messages and the main composer's `openArtifact` stay. [`docs/conversation.md`](../conversation.md) carries the contract changes.
- A file uploaded or made outside a Conversation is not an artifact and has no studio until it is saved as one; the Library's Edit on such a file first saves it as a version 1 artifact of the Conversation.

## Considered options

- **The file's thread as a filter of the Conversation** (the first mock-up). Rejected: the edits still land in Super Chat and in its context, which is what the person wanted gone.
- **Side chats as before ADR 0021.** Rejected: a general second place to talk was the problem; this is one place per file, opened only to edit it.
- **The chat in the side panel, beside Super Chat.** Rejected: two conversations on screen at once read as one; the studio gives the file the whole window while it is being edited.
- **Run the studio on the Conversation's bundle.** Rejected after review: that bundle speaks first and delegates, publishes a plan, counts work steps and offers `start_helper`, none of which belongs in a file's chat.
- **Let the canvas take hand edits during a studio turn and merge.** Rejected: a three-way merge of HTML by element id is more machinery than the case deserves; the turn is seconds long and the lit canvas says why.
- **A lock that refuses Super Chat's saves while the studio edits.** Rejected: the Conversation's helpers would fail mid-task on a file the person happens to have open; a stale notice to the studio and a hint to the Conversation are enough, since no version is lost.
