# Native PowerPoint is a second deck path, for charts and tables people edit in PowerPoint

An HTML deck (ADR 0011) is exported to PowerPoint by drawing the page, so its charts are HTML and CSS: they export as shapes, not as charts. People who want to open Edit Data in PowerPoint, or keep a real table, need a file built with PowerPoint's own chart and table parts.

- **A second path, chosen by the person's need.** The HTML deck stays the default for designed presentations (canvas editing, templates). The Muse builds a native `.pptx` only when the person wants a real PowerPoint with native charts and tables, or edits a `.pptx` they gave it. The rules are in `infra/omnigent/templates/decks.md`.
- **MiniMax's skill, ported.** The Muse follows MiniMax's `pptx-generator` skill (MIT), kept as written apart from Nova's paths, `artifact_save` delivery, and the rule that every chart and table value is read from the person's files and computed with pandas. It ships in the Computer image at `/usr/local/share/nova/skills/pptx-generator` and the prompt tells the Muse to read it when it takes this path, so the long skill costs nothing on other turns.
- **Runtime in the image.** PptxGenJS 4.0.1, react-icons, sharp (and python-pptx, markitdown for the skill's QA) are installed at build time on a fixed `NODE_PATH`, because containers cannot install anything at run time. PptxGenJS carries three upstream fixes the release lacks: the stray apostrophe in a chart workbook's table ref (Keynote and Quick Look drop the chart), a dangling series axis id in 2D charts (PowerPoint offers to repair the file), and zero values written as empty cells in Edit Data.
- **Preview in the panel.** A `.pptx` opens in a read-only preview drawn by `@aiden0z/pptx-renderer` (Apache-2.0), which parses the file in the browser. Chart categories are rewritten to the plain form on the preview's copy, since PptxGenJS writes them in a form the renderer does not read. If the file cannot be read, the panel shows the download-only message; the preview is never approximated.

## Considered options

- **Render server-side to images or PDF.** Rejected: the only faithful renderer is LibreOffice, whose image size was already ruled out.
- **`pptx-preview` (ISC).** Rejected: it drew nothing for a PptxGenJS deck with charts.
- **Put the whole skill in the Muse's prompt.** Rejected: about 1,800 lines on every turn for a minority of requests.

## Consequences

- The Computer image needs a rebuild for the runtime and the skill files; the prompt bundles are regenerated by `node infra/omnigent/render-agents.mjs`.
- The preview is a renderer's drawing, not PowerPoint's. Known gap: a table needs explicit row heights (the skill says so). The renderer drew pie, doughnut and varyColors-bar legend swatches in theme colors because those colors live on the data points; a pnpm patch (`patches/@aiden0z__pptx-renderer@1.3.0.patch`, Apache-2.0 source) makes each legend entry carry its point's color.
- `@aiden0z/pptx-renderer` depends on `mtx-decompressor` (MPL-2.0, file-level copyleft, used unmodified).
