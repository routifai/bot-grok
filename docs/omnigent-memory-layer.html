Omnigent + Nova · the memory layer

Every session starts from zero.
Every session starts with you.

Omnigent is an excellent engine: any harness, any runner, solid history management. What it doesn't have is a person. Each session knows its own transcript and nothing else. Nova adds a memory layer that the server composes into every turn, the same for every engine, private by default and bounded in size.

How it works

Four ideas do all the work

1 · The hook

Context comes from the server

Omnigent can append a <deployment_context> block to instructions. We moved who builds it: the runner asks POST /sessions/{id}/deployment-context, and with OMNIGENT_CONTEXT_PROVIDER=nova the server composes it in process. The runner never holds a secret or a database.

2 · Sections

Primitives compete for space

Memory (20, 32 KiB), goals (30, 8 KiB), episodes (40, 3 KiB), skills (45, 2 KiB), asks (60, 1 KiB). Gathered concurrently, sorted by priority, capped, and dropped whole from the bottom when over 48 KiB.

3 · Events

Episodes write themselves

On response.completed a detached task walks the turn back to your message; if a work tool ran, it upserts one episode keyed by turn. Ranking: title hits ×2, summary ×1, × 1/(1+age/60).

4 · Scope

Private is explicit

scope_from_labels returns private only for an explicit label. One resolver (private_actor) with an owner grant decides whose data a tool may touch, and every callback requires LEVEL_OWNER.
